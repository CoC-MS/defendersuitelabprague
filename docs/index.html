Part 1 – Configure

1Reduce the number of Global Admins

entra.microsoft.com → Entra ID → Roles & admins → Microsoft Entra ID roles
  1. Open the role list and find Global Administrator.
  2. Click the number of Global Administrators.
  3. Leave only 3 people with the Global Admin role, including MOD Administrator. Select Remove for the others.
  4. For the 2 remaining admins other than MOD Administrator, click Update and change the assignment to Eligible.
    ⚠️ Do NOT change the account you are signed in with (MOD Administrator).

2Create a group for the Global Admins

Entra ID → Groups → New group
  1. Create the group as shown in the picture (name it All Global Admins, security group).
  2. Add both remaining Global Admins as members – not MOD Administrator.

3Configure Passkey (FIDO2) settings

Entra ID → Authentication methods → Passkey (FIDO2)
  1. Click Passkey (FIDO2) → Configure → Add profile.
  2. Configure the profile as shown and Save.
  3. Go to Enable and target → Include → Select targets.
  4. Select the All Global Admins group and click Save.
ℹ️ In production you would add an allow list of GUIDs (only approved passkey models) and target all admins. In the lab we skip the GUIDs and use Global Admins only. The goal: allow only device-bound passkeys.

4Issue a Temporary Access Pass and register passkeys

Entra ID → Users → (each Global Admin except MOD Administrator) → Authentication methods
  1. Open the first Global Admin user → Authentication methods.
  2. Click Add authentication method → Temporary Access Pass. Set One-time use = Yes and click Add.
  3. Copy the TAP code shown on screen.
  4. Repeat for the other Global Admin account.
  5. Send both usernames + TAP codes to your phone (Teams, mail, …).
  6. On your phone open Microsoft Authenticator → Add work or school account. Enter the username and TAP for the first account and register the passkey.
  7. Repeat on the second account.
  8. Test: sign in with each account and choose the iOS or Android passkey sign-in method.

5Create an Authentication Context

Entra ID → Conditional Access → Authentication contexts
  1. Open Authentication contexts.
  2. Create one context named PIM role activation and make sure it is published to apps.

6Harden the Global Admin role in PIM

Entra ID → Roles & admins → Microsoft Entra ID roles → Global Administrator → Settings
  1. Open Global Administrator and click Settings.
  2. Click Edit.
  3. Configure the Activation tab as shown (use the PIM role activation authentication context).
    💡 For highly privileged roles add approvers. MOD Administrator can approve the 2 other Global Admins.
  4. Click Next: Assignment and configure as shown. Set expiration to 3 months (your tenant is valid for 3 months).
  5. Click Next: Notification and add your approvers' email addresses, separated by semicolons.
  6. Click Update.

7Protect admin accounts with a restricted management admin unit

Entra ID → Roles & admins → Admin units → Add
  1. Click Admin units → Add and create the unit named Global Admin Restricted Management. Enable Restricted management.
  2. Choose role User Administrator; select your current account + 1 more of your choice.
  3. Review + Create.
  4. In the new admin unit, add the All Global Admins security group.
  5. Go to Roles & admins → click User Administrator.
  6. Update your assignment from permanently active to permanently eligible, then Save.
ℹ️ This prevents anyone with a role – even other Global Admins – from deleting/editing the Global Admin group or resetting its members' passwords. Ideally also create 2 break-glass accounts the same way (with an active role assignment on both). Do that only if you have time; the point is to protect privileged accounts from internal mistakes.

8Create the Conditional Access policies

Entra ID → Conditional Access → Policies → New policy

9Access review for Entra roles

Entra ID → ID Governance → Access reviews → Microsoft Entra roles
  1. Open Microsoft Entra roles.
  2. Click New.
  3. Configure the settings marked in red. Skip Advanced.
  4. Click Start.
ℹ️ In production this review would cover several roles and Azure roles. Reviewing service principals needs an Entra Workload ID Premium license and can’t be tested in this lab.

10Add owners to the enterprise app

Entra ID → Enterprise apps → Mod Demo Platform App → Owners
  1. Open the enterprise app Mod Demo Platform App.
  2. Go to Owners → Add and add your own account and/or other accounts as owners.

11Access review for enterprise app owners

Entra ID → ID Governance → Access reviews → New access review
  1. Click New access review.
  2. Select Review access to a resource type (Applications).
  3. Select Applications, select all available applications, scope All users. Click Next: Reviews.
  4. Configure Reviews as shown, then Next: Settings.
  5. Configure Settings as shown, then Next: Review + Create.
  6. Name it App Owner reviews of existing Enterprise applications and click Create.
ℹ️ Reviewing app owners from time to time is very important – as shown in the Day 1 demo.

12Intune antivirus policy OPTIONAL

⚠️ Only for participants with a Windows 11 VM or physical Windows 11 device enrolled in Intune. Others can skip to Step 13.
intune.microsoft.com → Endpoint security → Antivirus → Create policy
  1. Click Create policy.
  2. Choose platform Windows and profile Microsoft Defender Antivirus. Click Create.
  3. Name it Windows 11 AV Policy → Next.
  4. Configure the settings as shown.
  5. Assign to All devices (or a security group with your device) and click Save.

13Mark DeepSeek as Unsanctioned

security.microsoft.com → SaaS apps → Cloud app catalog
  1. Open the Cloud app catalog and search for DeepSeek.
  2. Select Tag app → Unsanctioned.
  3. Confirm with Save.

14Set up case email notifications in Defender XDR

security.microsoft.com → Settings → Microsoft Defender XDR → Email notifications → Cases
  1. Go to Setup & configuration → Settings → Defender XDR.
  2. Open Email notifications → Cases → Add case notification rule.
  3. Basics: name it Send all notifications → Next. Configure as shown and select all Sources → Next.
  4. Recipients: add your own email address → Next → Submit.

15Create an app governance policy

security.microsoft.com → Assets → Applications → Create new policy
  1. Click Create new policy.
  2. Choose Permissions and New highly privileged app → Next.
  3. Choose severity High → Next.
  4. Choose No, I’ll customize the policy → Next.
  5. Choose All apps → Next.
  6. Leave as is → Next.
  7. Check Disable app → Next.
  8. Choose Active → Next.
  9. Review and click Submit.

16Create a risky app registration

entra.microsoft.com → App registrations → New registration

This app will trigger the policy from Step 15.

  1. Click New registration.
  2. Name it test (any name works) and click Register.
  3. Go to API permissions → Add a permission.
  4. Choose Microsoft Graph → Application permissions.
  5. Search Mail, press Enter, select Mail.ReadWrite and click Add permissions.
  6. Repeat: search ConditionalAccess, select Policy.ReadWrite.ConditionalAccess (and others if you like).
  7. Click Grant admin consent for Contoso → Yes.
ℹ️ Defender will raise an alert after some time and disable the app. See test T6.

17Final check before testing

  • 2 Global Admins eligible + MOD Administrator active
  • Passkeys registered on both admin accounts
  • Both Conditional Access policies are On
  • Access reviews (roles and app owners) started
  • DeepSeek tagged Unsanctioned, risky app created

Looks good? Continue to Part 2 – Test.

Part 2 – Test your configuration

T1Phishing-resistant sign-in

  1. Sign out, then sign in to entra.microsoft.com with one of the admins in the All Global Admins group.
  2. You are prompted for phishing-resistant MFA. If you try Authenticator push/code, it is not allowed.
✅ Result: The sign-in is protected against attacks like adversary-in-the-middle (advanced phishing).

T2Activate Global Admin in PIM

Entra → ID Governance → Privileged Identity Management → Microsoft Entra roles → My roles → Eligible roles
  1. Select Activate on Global Administrator.
  2. You are asked to re-authenticate with your passkey.
✅ Result: Even after a successful sign-in, role activation has a second layer of protection against AiTM phishing.

T3Complete the admin role access review

  1. Go to outlook.com and open the inbox of your account (or the reviewers you added).
  2. Open the mail from Microsoft Security: “Action required: Review access to the Global Administrator” and click Start review.
  3. Select one account, add a reason and click Deny. Approve all the others.
  4. Verify in the Entra portal that the Global Admin role was removed from the denied account.

T4Complete the app owner access review

  1. Open the review email in your inbox.
  2. Find the enterprise app with owners assigned and do the same as in T3 (deny at least one owner).
  3. Verify the denied app owners are removed from the app.

T5DeepSeek is blocked OPTIONAL

  1. On your Intune-enrolled VM/device, browse to deepseek.com (or another unsanctioned app).
  2. You should see a blocked message.
ℹ️ It can take up to 48 hours to fully work. Feel free to test later.

T6Risky app is detected and blocked

  1. Wait for the Defender alert email about the highly privileged app.
  2. Confirm in the Entra portal that the app registration has been disabled.
ℹ️ The email can take up to 12 hours (usually ~6 hours).

T7Admin accounts are protected

entra.microsoft.com → Users
  1. Open a Global Admin user that is in All Global Admins. You should not be able to delete the user or reset the password.
  2. Open the All Global Admins group: you should not be able to delete the group or add/remove members.
  3. In PIM, activate the eligible User Administrator role. Now all the actions above work.

🎉 Lab complete – thank you!

You protected privileged identities with phishing-resistant MFA, PIM, restricted management, access reviews and app governance.
